# Архитектура: лист «Ввод» (основное меню)

Актуально для финального файла `CryptoJournal. Test m2.xlsm`. Лист «Ввод» — единственное окно, через которое данные попадают в журналы «Торговля», «Лэндинг» и «Пул». Запись выполняет макрос `WriteEntry` (кнопка ЗАПИСАТЬ).

## 1. Принципы

1. Ввод только на листе «Ввод»; журналы заполняются макросом.
2. За один раз заполняется **один** раздел (Торговля, Лэндинг или Пул). Два раздела сразу — ошибка, статус «Два раздела».
3. Формульные ячейки заблокированы, ячейки ввода разблокированы. Защита листа без пароля.
4. Доступность разделов подсказывает серая подсветка (условное форматирование): когда заполнен один раздел, остальные становятся серыми.
5. Подсказки при вводе актива не делаем (решение принято).
6. Поле «Комментарий» убрано: нигде не сохранялось.

## 2. Макет (колонки B:G, лист печатается A1:H25)

| Блок | Диапазон | Заливка |
|---|---|---|
| Основные данные | B3:G5 (названия — строка 4, значения — строка 5) | — |
| Торговля | B7:C13 | #5E9E72 |
| Лэндинг | D7:E13 | #5E9E72 |
| Пул | F7:G13 | #8064A2 |
| Обратный расчёт | B15:G17 | #2F6F93 |
| Пояснения | B19:G24 (объединены, чёрный, размер 10) | — |

### Основные данные (строка 5)

| Ячейка | Поле | Примечание |
|---|---|---|
| B5 | Дата | формат `yyyy.mm.dd` |
| C5 | Актив 1 | текст |
| D5 | Актив 2 | выпадающий список `Список_Монеты`, ошибки не показываются, можно вписать новую монету |
| E5 | Пара | авто: `АКТИВ1/АКТИВ2` в верхнем регистре (заливка #FFF2CC) |
| F5 | Протокол | список `Список_Протокол`, **необязателен** |
| G5 | Статус | формула (см. раздел 5) |

### Торговля (C8:C13)

C8 Действие (Buy/Sell), C9 Кол-во, C10 Курс (биржевой, без комиссии), C11 Сумма (авто), C12 ID позиции (T-0001), C13 Закрыть (Частично/Полностью).

Сумма: `Кол-во × Курс × (1 + k × Комиссия/100)`, k = +1 для Buy, −1 для Sell.

### Лэндинг (E8:E13)

E8 Действие, E9 Кол-во, E10 Сумма (вводится), E11 Курс (авто = Сумма / Кол-во, 8 знаков), E12 ID позиции (L-0001), E13 Закрыть (Частично/Полностью).

### Пул (G8:G13, подписи F8:F13)

G8 Действие (Добавить / Частично / Закрыть), G9 ID пула (P-0001), G10 Кол-во 1, G11 Кол-во 2, G12 Min, G13 Max. Min и Max вводятся оба или ни одного; пусто = Web2, заполнено = Web3. Min/Max могут быть дробными и отрицательными, обязательно Min < Max.

### Обратный расчёт и комиссия (строки 15–17)

B17 Сумма, C17 Курс, D17 Кол-во (авто = `Сумма / (Курс × (1 − Комиссия/100))`), E17 **Комиссия, %** (по умолчанию 0,2; допустимо 0…100), F16:F17 кнопка ЗАПИСАТЬ (зелёная), G16:G17 кнопка ОЧИСТИТЬ (тёмно-красная, белый шрифт).

Комиссия общая для всех записей; на неё ссылаются формулы `Ввод!$E$17` на листах «Торговля» и «ИТОГО Торговля». При смене комиссии Break even уже записанных позиций пересчитывается (осознанное решение).

## 3. Разблокированные ячейки «Ввода»

B5, C5, D5, F5, C8, C9, C10, C12, C13, E8, E9, E10, E12, E13, G8, G9, G10, G11, G12, G13, B17, C17, E17. Остальное — формулы, заблокировано.

## 4. Режимы записи

Определение раздела: Торговля — заполнено C8:C10 или C12:C13; Лэндинг — E8:E10 или E12:E13; Пул — любая из G8:G13.

| ID | Действие | Результат |
|---|---|---|
| пусто | любое | новая позиция, ID выдаётся из счётчика на «Справочниках» (T, L, P) |
| указан | то же, что у позиции | увеличение: средневзвешенный курс, дата заменяется |
| указан | противоположное | закрытие: «Частично» — списывается Кол-во; «Полностью» — весь остаток. Закрытая часть уходит на «Закрытые» с тем же ID, остаток сохраняет прежний курс; при нулевом остатке строка очищается |

«Закрыть» заполняется только при указанном ID. ID можно вводить числом, макрос нормализует (`12` → `T-0012`).

Пул: «Добавить» без ID — новый пул; с ID — добавление в существующий. «Частично» и «Закрыть» требуют ID. Закрытый пул изменять нельзя. Min/Max допустимы только при «Добавить».

## 5. Статус (G5)

Формула, показывает, что произойдёт при нажатии ЗАПИСАТЬ. Значения: «Готово», «Два раздела», «Нет действия», «Нет Кол-ва», «Нет ID», «Нет курса», «Нет суммы», «Новая позиция», «Увеличение», «Закрытие частично», «Закрытие полностью», «Новый пул», «Добавить в пул», «Частично», «Закрытие пула», «Нужны Min и Max», «Нет ID пула», «Пул закрыт». Проблемные значения выделены бордовым (#722F37).

## 6. Справочники

- Колонка B «Протокол», C «Действие» (Buy, Sell).
- E3:G7 «Счётчики ID»: Торговля (T), Лэндинг (L), Пул (P).
- Колонка I «Монеты»: список для D5; новые монеты добавляются автоматически макросом при записи (с сортировкой).
- Именованные диапазоны: `Список_Протокол`, `Список_Действие_Торговля`, `Список_Монеты`.

## 7. Автодобавление

При успешной записи новая монета попадает в «Монеты», а новая пара — в листы «ИТОГО Торговля» + «ИТОГО» (Торговля), «ИТОГО Лэндинг» + «ИТОГО» (Лэндинг) или «ИТОГО ПУЛ» (Пул). Вручную пары добавлять не нужно.

## 8. Кнопки и очистка

После успешной записи вызывается очистка: сбрасываются C5, D5, F5 и все поля разделов. **Дата (B5), Комиссия (E17) и блок «Обратный расчёт» остаются.** Кнопка ОЧИСТИТЬ делает то же самое вручную. Кнопки — прозрачные прямоугольники с макросами `WriteEntry` и `ClearInput`.

## 9. Реализация

Файл `CryptoJournal. Test m2.xlsm`, собирается скриптами `tools/vbabuild.py` и `tools/mkxlsm.py` из исходника `archive/CryptoJournal. Test m2 (исходник без макросов).xlsx`. Код макросов: `macros/modTrade.bas` (подробно — README, раздел «Макросы»). Макрос защиту листов не снимает: пишет только в незаблокированные ячейки.

## 10. Открытые вопросы

Нет. Подсказка при вводе актива не планируется.
