# CRYPTO-JOURNAL

Crypto Trading Journal: журнал сделок в Excel (торговля, лэндинг, пулы ликвидности). Репозиторий содержит рабочую книгу Excel с макросами, описание дизайна и архитектуру логики.

## Статус

Финальная версия: `CryptoJournal.xlsm`. Интерфейс, логика полей, макросы (ЗАПИСАТЬ, ОЧИСТИТЬ) и кнопки готовы. Целевая версия Excel — 2021. Документация соответствует этому файлу.

## Основной файл

**`CryptoJournal.xlsm`** — финальная версия (книга с макросами). Раскладка «Ввода» в шесть колонок, Комиссия в `E17`, «Закрыть» (Частично / Полностью), раздел «Пул» с Min/Max (Web3), «Статус» формулой, защита формульных ячеек без пароля, макрос ЗАПИСАТЬ для Торговли, Лэндинга и Пула, кнопка ОЧИСТИТЬ, справочник «Монеты» (колонка I листа «Справочники»), автодобавление новых монет и пар в листы ИТОГО. Макросы лежат в `macros/` (`modTrade.bas`). Файл собирается скриптом `tools/mkxlsm.py` из исходника без макросов (`archive/CryptoJournal. Test m2 (исходник без макросов).xlsx`) и `macros/*.bas`; любые правки листов делаются в исходнике, затем файл пересобирается.

`archive/` — старые версии и исходник: `CryptoJournal_Input_Prototype_v7.xlsx` (прежний прототип), `CryptoJournal. Test m1.xlsx` (клон v7) и исходник m2 без макросов (из него собирается `.xlsm`).

## NewData v1 (рабочая копия)

`NewData v1.xlsm` — копия `CryptoJournal.xlsm` для дальнейшей работы (оригинал не менялся). Исходник без макросов: `archive/NewData v1 (исходник без макросов).xlsx`, макросы: `macros/NewData v1/` (`modTrade.bas`, `ThisWorkbook.cls.bas`), сборка: `python3 tools/mknewdata.py`. Изменения:

- **ID числовой.** На «Вводе» (Торговля, Лэндинг, Пул) ID можно вводить вручную: `T-456`, `L-456`, `P-456` или просто `456`; хранится как `Буква-0456`. Если такого ID нет ни в журнале, ни в «Закрытых», ЗАПИСАТЬ спросит и откроет новую позицию с этим ID; если ID уже был (даже закрыт) — отказ. Автоматические ID пропускают занятые номера. «Статус» показывает «Новая (ID вручную)» / «ID занят». Счётчики на «Справочниках» — только целые числа.
- **«История»** заполнена сделками из файла со сделками (104 пары, Покупка и Продажа), пары внесены в «ИТОГО».
- **Автодобавление пар.** Новая пара сама попадает в листы ИТОГО: при ЗАПИСАТЬ и при ручном вводе/вставке в «Историю» (→ ИТОГО), «Торговлю», «Лэндинг», «Пул», «Закрытые» (событие `Workbook_SheetChange`). Логика проверена в LibreOffice по формулам; макросы нужно проверить в Excel.
- **Лист «БАЛАНС»** (после «ИТОГО»): по каждой монете Пришло, Ушло, Дельта по журналам «Торговля», «Лэндинг», «Закрытые» и «История»; для пары X/Y покупка = пришёл X, ушёл Y, продажа наоборот; суммы с комиссией. «ИТОГО Торговля» и «ИТОГО Лэндинг» не суммируются (иначе двойной счёт), сверка идёт с листом «ИТОГО» (колонки «По ИТОГО», «Разница», ячейка «Сверка»). Монеты новой пары добавляются в «БАЛАНС» и в «Монеты» макросом.
- **Оформление:** Дельта 1, Дельта 2 и Break even — жирный курсив; колонки Кол-во, Курс, Сумма расширены на всех листах (кроме «Ввода»).


- `CryptoJournal.xlsm` — рабочая таблица.
- `specs/` — дизайн листов: `Дизайн Ввод.md` (общий дизайн «Ввода»), `Дизайн Ввод — Основные данные.md`, `Дизайн Ввод — Разделы.md`, `Дизайн Торговля и ИТОГО Торговля.md` (остальные листы), `Промт Торговля.md` (подробный промт листа «Торговля»), `Промт ИТОГО Торговля.md` (подробный промт листа «ИТОГО Торговля»), `Промт Лэндинг.md` и `Промт ИТОГО Лэндинг.md` (копии «Торговли» и «ИТОГО Торговля» с поправками для Лэндинга), `Промт ИТОГО.md` (общий свод Торговли и Лэндинга), `Промт Пул.md`, `Промт ИТОГО ПУЛ.md`, `Промт История.md` (лист «История»). Отдельного промта для листа «Закрытые» нет: он описан в `Дизайн Торговля и ИТОГО Торговля.md` (вкладка 8) и в `architecture/Архитектура Торговля.md` (разделы 3 и 9).
- `architecture/` — логика: `Архитектура Ввод — Основное меню.md`, `Архитектура Торговля.md`.
- `prompts/` — промт проекта для работы с ассистентом (`Промт проекта.md`).

Если документы расходятся: визуальные правила — в `specs/`, логика полей и сделок — в `architecture/`.

## Ключевые правила

- **Дата** везде в формате `ГГГГ.ММ.ДД`.
- **Пара** собирается автоматически из Актива 1 и Актива 2 (`SOL/USDT`), вручную не вводится, окрашена в #FFF2CC. Актив 1 и Актив 2 не могут совпадать.
- **Списки** «Протокол», «Действие» и «Монеты» берутся из листа «Справочники»; новые монеты макрос добавляет в «Монеты» сам. Протокол в основных данных необязателен. Подсказки при вводе актива не делаются.
- **Сумма (авто)** в Торговле: Buy = Кол-во × Курс × (1 + Комиссия / 100), Sell = Кол-во × Курс × (1 − Комиссия / 100). Комиссия лежит в `Ввод!$E$17`, по умолчанию 0.2 (в процентах, знак «%» не пишется), общая для всей книги.
- **ID сделок:** `T-0001` (Торговля), `L-0001` (Лэндинг), `P-0001` (Пул). Нумерация отдельная для каждого раздела, удалённые ID не используются повторно.
- **Раздел записи** определяется заполненным блоком (Тип убран): вводить можно только в один раздел (недоступные блоки серые, «Статус» показывает «Два раздела», макрос отказывает с сообщением).
- **P&L и Break even:** P&L и P&L% считаются только по полностью закрытым позициям (в «Закрытых» у частичных закрытий 0, результат позиции в последней строке её ID), Break even остатка учитывает прибыль снятых частей (`architecture/Архитектура Торговля.md`, раздел 9).
- **Открытые и закрытые сделки:** остаток остаётся в «Торговле», закрытая часть уходит в «Закрытые» (ID повторяется, суммы не задваиваются); полностью закрытая сделка есть только в «Закрытых». Частично закрытые сделки (Торговля и Лэндинг) подсвечены фоном #FDE9D9. Закрытые сделки Лэндинга лежат в том же листе «Закрытые» с ID `L-…`. Режим записи в «Торговлю» и «Лэндинг» выбирается по ID и Действию: ID пусто — новая позиция, ID заполнен и Действие противоположное — закрытие, то же — увеличение позиции со средневзвешенным курсом (`architecture/Архитектура Торговля.md`, раздел 7). Закрытие задаётся полем «Закрыть» (Частично / Полностью).
- **Тестовые данные убраны:** журналы («Торговля», «Лэндинг», «Закрытые», «Пул»), списки пар в листах ИТОГО, дата и калькулятор на «Вводе» пусты, счётчики ID на «Справочниках» = 0 (комиссия 0,2 и список «Монеты» оставлены). Примеры с цифрами в промтах (`T-0028`, `P-0009…` и т. п.) описывают прежний демо-набор и приведены как иллюстрация правил. Демо-версия лежит в истории git (коммит 202286f).
- **Протокол на «Пуле»** выбирается из выпадающего списка (D5:D300, тот же список, что на «Вводе»).
- **Автофильтр** на строке меню оставлен на всех листах с таблицами (у всех колонок).
- **Зебра строк** в «Торговле», «Лэндинге», «Закрытых» и трёх листах «ИТОГО» (до строки 300; «Пул» и «ИТОГО ПУЛ» тоже растянуты до 300 с такой же зеброй) задана условным форматированием: полосы не ломаются при протягивании и вставке; жёлтые автоматические колонки Сумма не затрагиваются, подсветка частично закрытых имеет приоритет.
- **Вместимость журналов:** формулы и оформление в «Торговле», «Лэндинге» и «Закрытых» протянуты до строки 300; строки для пар в «ИТОГО Торговля», «ИТОГО Лэндинг» и «ИТОГО» тоже до 300 (пары добавляет макрос при записи, диапазоны считают строки 5–300). Для вставки исторических данных вводимые колонки заполняются значениями, колонки Сумма, Дельта, P&L и Break even с формулами не трогаются (в «Закрытых» Сумма теперь тоже формула). Область печати листов осталась прежней (A1:N17 и т. п.).
- **Обратный расчёт** — калькулятор, в журнал не записывается.
- Листы защищены без пароля: на «Вводе» редактируются только окна ввода, на журналах — ввод и форматирование (формулы заблокированы). Макрос защиту не снимает, он пишет только в незаблокированные ячейки.
- **«Статус» (G5)** — формула: показывает, что сделает ЗАПИСАТЬ («Новая позиция», «Увеличение», «Закрытие частично» и т. д.) или чего не хватает («Нет ID», «Нет Кол-ва» …); проблемные значения бордовые.
- **Пул, Min/Max:** оба значения или ни одного; пусто = Web2, заполнено = Web3; могут быть дробными и отрицательными, Min < Max.

## Открыто

- Break even в «Закрытых» не считается (колонка убрана). P&L и P&L% по частично закрытым позициям: прибыль не фиксируется до полного закрытия, а уменьшает Break even остатка (`architecture/Архитектура Торговля.md`, раздел 9); проверено на `T-0028`, `T-0029`.
- Пул: частичное закрытие реализовано как учёт «внесено / выведено» без долей (результат считается только при статусе «Закрыт»); действия на «Вводе»: «Добавить, Частично, Закрыть»; P&L по пулам не считается (`specs/Промт Пул.md`, п. 10).
- **Очистка:** после успешной записи очищаются только окна разделов; Дата, Актив 1/2, Протокол, Комиссия и «Обратный расчёт» остаются. Кнопка ОЧИСТИТЬ дополнительно сбрасывает Актив 1, Актив 2 и Протокол.
- Комиссия общая: при её смене Break even уже записанных позиций пересчитывается.
- «ИТОГО ПУЛ» не использует Min/Max; Min/Max можно задать или обновить только при действии «Добавить».
- Запись из «Ввода» в «Торговлю»: соответствие ячеек — `architecture/Архитектура Торговля.md` (раздел 7), закрытие — раздел 6. Курс пишется не более чем с 8 знаками.


## Макросы (VBA)

ЗАПИСАТЬ (`WriteEntry`) определяет раздел по заполненным полям (Торговля — C8:C10 / C12:C13, Лэндинг — E8:E10 / E12:E13, Пул — G8:G13; больше одного раздела — отказ), проверяет данные, выдаёт ID из счётчиков «Справочников», пишет в журналы и «Закрытые», добавляет новые монеты в «Монеты» и новые пары в листы ИТОГО, затем очищает окна разделов (Дата, активы и протокол остаются). ОЧИСТИТЬ (`ClearInput`) чистит разделы, Актив 1/2 и Протокол вручную. Макрос не снимает защиту листов. Код — единственный модуль `macros/modTrade.bas` (константы только в начале модуля, `Option Explicit`). Сборка: `python3 tools/mkxlsm.py` (читает исходник из `archive/` и `macros/*.bas`, пишет `.xlsm` в корень). Логика проверена в LibreOffice; кнопки и события в Excel проверяет пользователь. Файл, скачанный из интернета, нужно разблокировать (Свойства → Разблокировать) и нажать «Включить содержимое».
