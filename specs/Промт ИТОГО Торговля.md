# Промт — лист «ИТОГО Торговля»

## Назначение

Подробный промт для ассистента: как построить, проверить и дорабатывать лист «ИТОГО Торговля» в `CryptoJournal_Input_Prototype_v7.xlsx`. Промт самодостаточен: по нему лист можно воспроизвести с нуля. Общие правила проекта — `prompts/Промт проекта.md`, дизайн — `specs/Дизайн Торговля и ИТОГО Торговля.md`, логика сделок — `architecture/Архитектура Торговля.md`, соседний лист — `specs/Промт Торговля.md`. Если документы расходятся: визуальные правила — в `specs/`, логика полей и сделок — в `architecture/`.

## 1. Роль листа

Лист «ИТОГО Торговля» — **свод по парам** раздела «Торговля». Одна строка = одна пара (`ETH/USDT`). Значения берутся из двух листов:

- «Торговля» — открытые позиции и остатки частично закрытых сделок;
- «Закрытые» — закрытые части и полностью закрытые сделки. Лист общий для Торговли и Лэндинга: в «ИТОГО Торговля» берутся только строки с ID `T-…`.

Одно и то же количество лежит ровно в одном из этих листов, поэтому в сумму оно попадает один раз (задвоения нет). Лист ничего не вводит руками, кроме списка пар в колонке B. Макросы (VBA) в прототипе не используются.

## 2. Геометрия и общие правила оформления

- Колонка A — поле шириной 2.5. Таблица занимает колонки **B:M**.
- Строки 1–2: полоса заголовка B1:M2 (объединена), заливка #255B78, белый Calibri 16 Bold, текст `CRYPTO JOURNAL • ИТОГО ТОРГОВЛЯ`. Высота строк 21.
- Строка 3: узкий интервал, высота 10. Строка 4: меню одной строкой, высота 28, белый Calibri 11 Bold Italic, по центру.
- Строки данных с 5-й по 300-ю, высота 22. Зебра: нечётные строки #FFFDF3, чётные белые. Текст #244E62, Calibri 11, по центру, без переноса, тонкая рамка #6F9EB3.
- Между блоками: в шапке толстый белый просвет, в строках данных средняя линия #255B78.
- Сетка скрыта, ярлык вкладки #722F37 (тёмно-бордовый), ориентация печати альбомная, область печати A1:N13.
- Закреплены строка меню и колонка B (панель на C5). Масштаб 100%.
- Автофильтр на строке меню оставлен (кнопки у всех колонок, диапазон B4:M300).
- Числа: `#,##0.00######;[Red]-#,##0.00######` (отрицательные красным).

## 4. Формулы (строка 5 как образец, строки 5–300)

В формулах `Торговля!` и `Закрытые!` диапазоны строк 5–300; из «Закрытых» берутся только строки, у которых ID начинается с `T-` (`SUMIFS`/`COUNTIFS` с критерием `Закрытые!B, "T-*"`, в `SUMPRODUCT` множитель `LEFT(Закрытые!B,2)="T-"`). Колонки «Закрытых»: E Пара, F Кол-во покупки, G Курс покупки, H Сумма покупки, I Кол-во продажи, J Курс продажи, K Сумма продажи, L Дельта 1, M Дельта 2.

**Блок «Покупка»**
- **C Покупка** = `SUMIFS(Торговля!F, Торговля!E, пара) + SUMIFS(Закрытые!F, Закрытые!E, пара)`; если итог 0, ячейка пустая.
- **D Курс** = средневзвешенный курс: `(SUMPRODUCT(Торговля: пара × F × G) + SUMPRODUCT(Закрытые: пара × F × G)) / C`; пусто, если C пусто.
- **E Сумма** = `SUMIFS(Торговля!H, …) + SUMIFS(Закрытые!H, …)`; пусто, если C пусто.

**Блок «Продажа»** — то же для колонок: F ← «Торговля» I и «Закрытые» I; G = взвешенный курс по «Торговля» I × J и «Закрытые» I × J; H ← «Торговля» K и «Закрытые» K.

**Блок «Дельта»** («Торговля» + «Закрытые»)
- **I Дельта 1** = `ROUND(SUMIFS(Торговля!L, Торговля!E, пара) + SUMIFS(Закрытые!L, Закрытые!E, пара, Закрытые!B, "T-*"), 8)`; пусто, если по паре нет строк ни в «Торговле», ни в «Закрытых». Равна Покупка − Продажа (количество) по паре.
- **J Дельта 2** = то же с колонкой M обоих листов (`Торговля!M`, `Закрытые!M`); пусто там же. Равна Сумма продажи − Сумма покупки по паре.

**Блок «P&L»**
- **K P&L** = сумма P&L строк «Закрытых» этой пары (`T-*`): `IF($B="","",ROUND(SUMIFS(Закрытые!N,Закрытые!E,$B,Закрытые!B,"T-*"),8))`. Значение есть у каждой пары из списка (0, если полностью закрытых позиций нет): нули частичных закрытий просто прибавляются к результатам остальных, а статистика по паре не пропадает. Считается только по полностью закрытым позициям (частичные закрытия дают 0, `architecture/Архитектура Торговля.md`, раздел 9).
- **L P&L%** = K / стоимость полностью закрытых позиций пары × 100, стоимость = `SUMPRODUCT((Закрытые!E=$B)*(LEFT(Закрытые!B,2)="T-")*(COUNTIF(Торговля!B,Закрытые!B)=0)*MIN-кол-во*Закрытые!G)`; 0, если стоимость равна 0.
- **M Break even** =
  `IF(OR(ROUND(N(C)-N(F),8)=0, 1-N(Ввод!$J$19)/100<=0), "", IF(N(C)>N(F), (N(E)-N(H))/((N(C)-N(F))*(1-N(Ввод!$J$19)/100)), (N(H)-N(E))/((N(F)-N(C))*(1+N(Ввод!$J$19)/100))))`

Формулы совместимы с Excel 2021: без динамических массивов (`FILTER`, `UNIQUE`, `SORT`, `XLOOKUP` не использовать).

## 5. Смысл расчётов

Курсы D и G эффективные: комиссия уже внутри (Buy × (1 + f/100), Sell × (1 − f/100)), поэтому в P&L комиссия отдельно не вычитается.

**P&L** — результат **полностью закрытых** позиций пары: сумма колонки P&L листа «Закрытые» по строкам этой пары с ID `T-…`. Частичные закрытия дают 0, результат позиции появляется в последней строке её ID (`architecture/Архитектура Торговля.md`, раздел 9). Единица — котируемый актив пары (для BTC/USDT это USDT). У каждой пары из списка значение есть всегда (0, если полностью закрытых позиций нет). Комиссия уже внутри курсов, отдельно не вычитается.

**P&L%** — `K / стоимость полностью закрытых позиций пары × 100`, стоимость = Σ MIN(Кол-во покупки, Кол-во продажи) × Курс покупки по их строкам в «Закрытых» (строки, чей ID уже нет в листе «Торговля»); 0, если стоимость равна 0.

**Break even** — биржевой курс, по которому закрытие остатка делает итоговый P&L по паре равным нулю с учётом комиссии закрытия f (комиссия с листа «Ввод», как в Break even листа «Торговля»). Остаток = Покупка − Продажа.

| Остаток | Формула | Смысл |
|---|---|---|
| Покупка > Продажа (остаток куплен) | `(E − H) / (остаток × (1 − f/100))` | курс продажи остатка, при котором вся пара выходит в ноль |
| Продажа > Покупка (остаток продан) | `(H − E) / (остаток × (1 + f/100))` | курс выкупа остатка, при котором вся пара выходит в ноль |
| Покупка = Продажа | пусто | остатка нет |

Реализованная прибыль учтена: она снижает Break even остатка (и наоборот, убыток поднимает). Отрицательное значение Break even: для остатка в покупке прибыль уже покрывает всю стоимость остатка (в ноль при любом курсе), для остатка в продаже безубыточность недостижима.

**Отличие от Дельты.** Дельта 1 и Дельта 2 — это Покупка − Продажа (количество) и Сумма продажи − Сумма покупки по паре, то есть сумма Дельт всех строк «Торговли» и «Закрытых». P&L учитывает только полностью закрытые позиции, поэтому P&L и Дельта 2 различаются.

### Пример (комиссия 0.2%)

| Пара | Покупка (кол-во / курс) | Продажа (кол-во / курс) | P&L | P&L% | Остаток | Break even |
|---|---|---|---|---|---|---|
| ADA/USDT | 150 / 0.61456 | 150 / 0.687955 | 11.0092 | 11.94 | нет | пусто |
| BNB/USDT | 2 / 586.17 | 5 / 598.80 | 0 | 0 | 3 в продаже | 606.01 |
| BTC/USDT | 0.35 / 62 038.114 | 0.25 / 62 474.80 | 117.76 | 0.76 | 0.1 в покупке | 61 068.54 |
| ETH/BTC | 2 / 0.0510018 | 3.5 / 0.051882 | 0.00099 | 0.97 | 1.5 в продаже | 0.052949 |
| ETH/USDT | 4 / 3 210.408 | 2.5 / 3 373.24 | 0 | 0 | 1.5 в покупке | 2 944.91 |

## 6. Связи с другими листами

## 7. Проверки после любой правки

1. Пересчитать таблицу, ошибок (`#NAME?`, `#VALUE!`, `#REF!`, `#DIV/0!`) нет ни на одном листе.
2. Сверить итоги с независимым расчётом из сырых данных «Торговли» и «Закрытых»: количество и сумма по паре, P&L, P&L%, Break even.
3. Обратная проверка Break even: для остатка в покупке `Break even × (1 − f/100) × остаток + (H − E) = 0`, для остатка в продаже `(H − E) − Break even × (1 + f/100) × остаток = 0`.
4. Вписать новую пару в свободную строку 23–300: значения появляются, ошибок нет. Пара без сделок даёт пустые ячейки.
5. Покупки и продажи не задваиваются: позиция не лежит одновременно в «Торговле» и «Закрытых» целиком.
6. Документация (`specs/`, `architecture/`, `README.md`) совпадает с файлом, в репозитории одна рабочая версия таблицы.
7. После каждого изменения файла присылать актуальный xlsx в чат.

## 9. Открытые вопросы

- P&L по закрытым ID отдельно уже есть в «Закрытых» (колонка P&L), а в этом листе складывается по полностью закрытым позициям пары.
- Нужна ли оценка нереализованной части по рыночному курсу: для этого пришлось бы вводить текущий курс по каждой паре.
- Break even в «Закрытых» не считается; лист «ИТОГО» считает P&L и Break even по общим итогам Торговли и Лэндинга.
- Фиксировать ли комиссию в строке на момент сделки, чтобы Break even не менялся при смене комиссии.
