# Промт — лист «ИТОГО Лэндинг»

## Назначение

Подробный промт для ассистента: как построить, проверить и дорабатывать лист «ИТОГО Лэндинг» в `CryptoJournal_Input_Prototype_v7.xlsx`. Лист «ИТОГО Лэндинг» — **точная копия листа «ИТОГО Торговля»**: ничего нового не придумывается, все правила и расчёты те же. Этот промт дублирует `specs/Промт ИТОГО Торговля.md` с поправками на раздел «Лэндинг» (источник данных, нет закрытых сделок). Промт самодостаточен: по нему лист можно воспроизвести с нуля. Общие правила проекта — `prompts/Промт проекта.md`, дизайн — `specs/Дизайн Торговля и ИТОГО Торговля.md`, логика сделок — `architecture/Архитектура Торговля.md`, соседний лист — `specs/Промт Лэндинг.md`. Если документы расходятся: визуальные правила — в `specs/`, логика полей и сделок — в `architecture/`.

## 1. Роль листа

Лист «ИТОГО Лэндинг» — **свод по парам** раздела «Лэндинг». Одна строка = одна пара (`ETH/USDT`). Значения берутся **только с листа «Лэндинг»** (открытые позиции и остатки). Листа закрытых сделок Лэндинга пока нет, поэтому часть «закрытые» из «ИТОГО Торговля» здесь отсутствует. Лист «Закрытые» относится только к «Торговле» и сюда не подключён, иначе закрытые сделки Торговли попали бы в итоги Лэндинга. Лист ничего не вводит руками, кроме списка пар в колонке B. Макросы (VBA) в прототипе не используются.

## 2. Геометрия и общие правила оформления

- Колонка A — поле шириной 2.5. Таблица занимает колонки **B:M**.
- Строки 1–2: полоса заголовка B1:M2 (объединена), заливка #255B78, белый Calibri 16 Bold, текст `CRYPTO JOURNAL • ИТОГО ЛЭНДИНГ`. Высота строк 21.
- Строка 3: узкий интервал, высота 10. Строка 4: меню одной строкой, высота 28, белый Calibri 11 Bold Italic, по центру.
- Строки данных с 5-й по 12-ю, высота 22. Зебра: нечётные строки #FFFDF3, чётные белые. Текст #244E62, Calibri 11, по центру, без переноса, тонкая рамка #6F9EB3.
- Между блоками: в шапке толстый белый просвет, в строках данных средняя линия #255B78.
- Сетка скрыта, ярлык вкладки #722F37 (тёмно-бордовый), ориентация печати альбомная, область печати A1:N13.
- Закреплены строка меню и колонка B (панель на C5). Масштаб 100%.
- Фильтры и сортировка (стрелки в строке меню) решено убрать со всех листов; в прототипе на «ИТОГО Лэндинг», как на «ИТОГО Торговля», автофильтр пока остался (B4:M12), убирается по отдельной команде.
- Числа: `#,##0.00######;[Red]-#,##0.00######` (отрицательные красным).

## 4. Формулы (строка 5 как образец, строки 5–12)

В формулах диапазоны листа «Лэндинг» берутся со строки 5 по 200. Колонки «Лэндинга»: E Пара, F Покупка (кол-во), G Курс, H Сумма, I Продажа (кол-во), J Курс, K Сумма.

**Блок «Покупка»**
- **C Покупка** = `SUMIFS(Лэндинг!F, Лэндинг!E, пара)`; если итог 0, ячейка пустая.
- **D Курс** = средневзвешенный курс: `SUMPRODUCT((Лэндинг!E=пара) × Лэндинг!F × Лэндинг!G) / C`; пусто, если C пусто.
- **E Сумма** = `SUMIFS(Лэндинг!H, Лэндинг!E, пара)`; пусто, если C пусто.

**Блок «Продажа»** — то же для колонок: F ← «Лэндинг» I; G = взвешенный курс по «Лэндинг» I × J; H ← «Лэндинг» K.

Формула C5 целиком: `=IF(SUMIFS(Лэндинг!$F$5:$F$200,Лэндинг!$E$5:$E$200,$B5)=0,"",SUMIFS(Лэндинг!$F$5:$F$200,Лэндинг!$E$5:$E$200,$B5))`.

**Блок «Дельта»** — в «ИТОГО Торговля» считается по закрытым частям из «Закрытых». У Лэндинга закрытых нет, поэтому **I и J пока пустые** (без формул). Когда появится лист закрытых Лэндинга, колонки заполняются по образцу «ИТОГО Торговля»: I = `ROUND(SUMIFS(<лист закрытых>!Дельта 1, <лист закрытых>!Пара, пара), 8)`, J = `ROUND(I / SUMIFS(<лист закрытых>!Сумма покупки, …, пара) × 100, 2)`; пусто, если по паре нет закрытых строк.

**Блок «P&L»** (формулы идентичны «ИТОГО Торговля»)
- **K P&L** = `IF(MIN(N(C),N(F))<=0,"",ROUND(MIN(N(C),N(F))*(N(G)-N(D)),8))`
- **L P&L%** = `IF(MIN(N(C),N(F))<=0,"",IF(N(D)=0,"",ROUND((N(G)/N(D)-1)*100,2)))`
- **M Break even** =
  `IF(OR(ROUND(N(C)-N(F),8)=0, 1-N(Ввод!$J$19)/100<=0), "", IF(N(C)>N(F), (N(E)-N(H))/((N(C)-N(F))*(1-N(Ввод!$J$19)/100)), (N(H)-N(E))/((N(F)-N(C))*(1+N(Ввод!$J$19)/100))))`

Формулы совместимы с Excel 2021: без динамических массивов (`FILTER`, `UNIQUE`, `SORT`, `XLOOKUP` не использовать).

## 5. Смысл расчётов

Курсы D и G эффективные: комиссия уже внутри (Buy × (1 + f/100), Sell × (1 − f/100)), поэтому в P&L комиссия отдельно не вычитается.

**P&L** — реализованный результат по паре по средней цене: объём, который по паре и куплен, и продан (меньшее из C и F), умножается на разницу средних курсов продажи и покупки. Единица — котируемый актив пары. Если по паре нет покупок или продаж, ячейка пустая.

**P&L%** — та же разница в процентах: `(G / D − 1) × 100`.

**Break even** — биржевой курс, по которому закрытие остатка делает итоговый P&L по паре равным нулю с учётом комиссии закрытия f (комиссия с листа «Ввод»). Остаток = Покупка − Продажа.

| Остаток | Формула | Смысл |
|---|---|---|
| Покупка > Продажа (остаток куплен) | `(E − H) / (остаток × (1 − f/100))` | курс продажи остатка, при котором вся пара выходит в ноль |
| Продажа > Покупка (остаток продан) | `(H − E) / (остаток × (1 + f/100))` | курс выкупа остатка, при котором вся пара выходит в ноль |
| Покупка = Продажа | пусто | остатка нет |

Реализованная прибыль учтена: она снижает Break even остатка (и наоборот, убыток поднимает). Отрицательное значение Break even: для остатка в покупке прибыль уже покрывает всю стоимость остатка (в ноль при любом курсе), для остатка в продаже безубыточность недостижима.

**Отличие от Дельты.** Дельта считается только по закрытым частям, привязанным к ID. P&L считается по всему количеству пары средней ценой, в том числе когда покупки и продажи лежат на листе «Лэндинг» в разных строках и не связаны ID.

### Пример (комиссия 0.2%, демо-данные)

| Пара | Покупка (кол-во / курс) | Продажа (кол-во / курс) | P&L | P&L% | Остаток | Break even |
|---|---|---|---|---|---|---|
| BNB/USDT | нет | 3 / 598.80 | пусто | пусто | 3 в продаже | 597.60 |
| BTC/USDT | 0.1 / 62 124 | нет | пусто | пусто | 0.1 в покупке | 62 248.50 |
| ETH/BTC | нет | 1.5 / 0.052395 | пусто | пусто | 1.5 в продаже | 0.05229 |
| ETH/USDT | 3 / 3 211.744 | 1.5 / 3 393.20 | 272.184 | 5.65 | 1.5 в покупке | 3 036.36 |
| SOL/USDT | 25 / 146.292 | 40 / 150.199 | 97.675 | 2.67 | 15 в продаже | 156.40 |

Значения демонстрационные, взяты из файла прототипа. Пары без покупок или без продаж дают пустые P&L и P&L%, а Break even считается по остатку.

## 6. Связи с другими листами

- «Лэндинг» → «ИТОГО Лэндинг»: единственный источник чисел.
- «Ввод» → Break even: формула читает комиссию с листа «Ввод».
- «Закрытые» и «ИТОГО Торговля» к Лэндингу не относятся. «ИТОГО» остаётся копией со старыми данными.

## 7. Проверки после любой правки

1. Пересчитать таблицу, ошибок (`#NAME?`, `#VALUE!`, `#REF!`, `#DIV/0!`) нет ни на одном листе.
2. Сверить итоги с независимым расчётом из сырых данных листа «Лэндинг»: количество и сумма по паре, P&L, P&L%, Break even.
3. Обратная проверка Break even: для остатка в покупке `Break even × (1 − f/100) × остаток + (H − E) = 0`, для остатка в продаже `(H − E) − Break even × (1 + f/100) × остаток = 0`.
4. Вписать новую пару в свободную строку 10–12: значения появляются, ошибок нет. Пара без сделок даёт пустые ячейки.
5. Формулы листа не ссылаются на «Торговля» и «Закрытые».
6. Документация (`specs/`, `architecture/`, `README.md`) совпадает с файлом, в репозитории одна рабочая версия таблицы.
7. После каждого изменения файла присылать актуальный xlsx в чат.
