# Промт — лист «ИТОГО Лэндинг»

## Назначение

Подробный промт для ассистента: как построить, проверить и дорабатывать лист «ИТОГО Лэндинг» в `CryptoJournal_Input_Prototype_v7.xlsx`. Лист «ИТОГО Лэндинг» — **точная копия листа «ИТОГО Торговля»**: ничего нового не придумывается, все правила и расчёты те же. Этот промт дублирует `specs/Промт ИТОГО Торговля.md` с поправками на раздел «Лэндинг» (источник данных: «Лэндинг» и закрытые части `L-…` из «Закрытых»). Промт самодостаточен: по нему лист можно воспроизвести с нуля. Общие правила проекта — `prompts/Промт проекта.md`, дизайн — `specs/Дизайн Торговля и ИТОГО Торговля.md`, логика сделок — `architecture/Архитектура Торговля.md`, соседний лист — `specs/Промт Лэндинг.md`. Если документы расходятся: визуальные правила — в `specs/`, логика полей и сделок — в `architecture/`.

## 1. Роль листа

Лист «ИТОГО Лэндинг» — **свод по парам** раздела «Лэндинг». Одна строка = одна пара (`ETH/USDT`). Лист считается **аналогично «ИТОГО Торговля»**: значения берутся с листа «Лэндинг» (открытые позиции и остатки) и с общего листа «Закрытые» (закрытые части; только строки с ID `L-…`, строки `T-…` Торговли не учитываются). Закрытые сделки Лэндинга вручную переносятся в «Закрытые». «ИТОГО Торговля» к Лэндингу не относится. Подробный промт «Закрытых» и «Торговли» — `specs/Промт ИТОГО Торговля.md`.

## 4. Формулы (строка 5 как образец, строки 5–300)

В формулах диапазоны листов «Лэндинг» и «Закрытые» берутся со строки 5 по 300. Колонки «Лэндинга»: E Пара, F Покупка (кол-во), G Курс, H Сумма, I Продажа (кол-во), J Курс, K Сумма. Колонки «Закрытых»: B ID, E Пара, F Кол-во покупки, G Курс покупки, H Сумма покупки, I Кол-во продажи, J Курс продажи, K Сумма продажи, L Дельта 1, M Дельта 2. Из «Закрытых» берутся только строки, у которых ID начинается с `L-`.

**Блок «Покупка»**
- **C Покупка** = `SUMIFS(Лэндинг!F, Лэндинг!E, пара) + SUMIFS(Закрытые!F, Закрытые!E, пара, Закрытые!B, "L-*")`; если итог 0, ячейка пустая.
- **D Курс** = средневзвешенный курс: `(SUMPRODUCT((Лэндинг!E=пара) × Лэндинг!F × Лэндинг!G) + SUMPRODUCT((Закрытые!E=пара) × (ID начинается с L-) × Закрытые!F × Закрытые!G)) / C`; пусто, если C пусто.
- **E Сумма** = `SUMIFS(Лэндинг!H, …) + SUMIFS(Закрытые!H, …, Закрытые!B, "L-*")`; пусто, если C пусто.

**Блок «Продажа»** — то же для колонок: F ← «Лэндинг» I и «Закрытые» I; G = взвешенный курс по «Лэндинг» I × J и «Закрытые» I × J; H ← «Лэндинг» K и «Закрытые» K.

Формула C5 целиком: `=IF(SUMIFS(Лэндинг!$F$5:$F$300,Лэндинг!$E$5:$E$300,$B5)+SUMIFS(Закрытые!$F$5:$F$300,Закрытые!$E$5:$E$300,$B5,Закрытые!$B$5:$B$300,"L-*")=0,"",SUMIFS(Лэндинг!$F$5:$F$300,Лэндинг!$E$5:$E$300,$B5)+SUMIFS(Закрытые!$F$5:$F$300,Закрытые!$E$5:$E$300,$B5,Закрытые!$B$5:$B$300,"L-*"))`.

**Блок «Дельта»** — как в «ИТОГО Торговля»: сумма Дельты строк «Лэндинга» и строк `L-*` из «Закрытых» по паре. I = `ROUND(SUMIFS(Лэндинг!L, Лэндинг!E, пара) + SUMIFS(Закрытые!L, Закрытые!E, пара, Закрытые!B, "L-*"), 8)`; J — то же с колонкой M; пусто, если по паре нет строк ни в «Лэндинге», ни в «Закрытых». Равны Покупка − Продажа (количество) и Сумма продажи − Сумма покупки по паре. Формулы стоят в строках 5–12.

**Блок «P&L»** (формулы идентичны «ИТОГО Торговля»)
- **K P&L** = сумма P&L строк «Закрытых» этой пары (`L-*`): `IF($B="","",IF(COUNTIFS(Закрытые!E,$B,Закрытые!B,"L-*")=0,"",ROUND(SUMIFS(Закрытые!N,Закрытые!E,$B,Закрытые!B,"L-*"),8)))`. Считается только по полностью закрытым позициям (частичные закрытия дают 0, `architecture/Архитектура Торговля.md`, раздел 10).
- **L P&L%** = K / стоимость полностью закрытых позиций пары × 100, стоимость = `SUMPRODUCT((Закрытые!E=$B)*(LEFT(Закрытые!B,2)="L-")*(COUNTIF(Лэндинг!B,Закрытые!B)=0)*MIN-кол-во*Закрытые!G)`; пусто, если стоимость равна 0.
- **M Break even** =
  `IF(OR(ROUND(N(C)-N(F),8)=0, 1-N(Ввод!$J$19)/100<=0), "", IF(N(C)>N(F), (N(E)-N(H))/((N(C)-N(F))*(1-N(Ввод!$J$19)/100)), (N(H)-N(E))/((N(F)-N(C))*(1+N(Ввод!$J$19)/100))))`

Формулы совместимы с Excel 2021: без динамических массивов (`FILTER`, `UNIQUE`, `SORT`, `XLOOKUP` не использовать).

## 5. Смысл расчётов

Курсы D и G эффективные: комиссия уже внутри (Buy × (1 + f/100), Sell × (1 − f/100)), поэтому в P&L комиссия отдельно не вычитается.

**P&L** — реализованный результат по паре по средней цене: объём, который по паре и куплен, и продан (меньшее из C и F), умножается на разницу средних курсов продажи и покупки. Единица — котируемый актив пары. Если по паре нет покупок или продаж, ячейка пустая.

**P&L%** — та же разница в процентах: `(G / D − 1) × 100`.

**Break even** — биржевой курс, по которому закрытие остатка делает итоговый P&L по паре равным нулю с учётом комиссии закрытия f (комиссия с листа «Ввод»). Остаток = Покупка − Продажа.

| Остаток | Формула | Смысл |
|---|---|---|
| Покупка > Продажа (остаток куплен) | `(E − H) / (остаток × (1 − f/100))` | курс продажи остатка, при котором вся пара выходит в ноль |
| Продажа > Покупка (остаток продан) | `(H − E) / (остаток × (1 + f/100))` | курс выкупа остатка, при котором вся пара выходит в ноль |
| Покупка = Продажа | пусто | остатка нет |

Реализованная прибыль учтена: она снижает Break even остатка (и наоборот, убыток поднимает). Отрицательное значение Break even: для остатка в покупке прибыль уже покрывает всю стоимость остатка (в ноль при любом курсе), для остатка в продаже безубыточность недостижима.

**Отличие от Дельты.** Дельта — это Покупка − Продажа (количество) и Сумма продажи − Сумма покупки по паре. P&L считается по средней цене пары и учитывает только совпавший объём, поэтому P&L и Дельта 2 различаются.

| BNB/USDT | 1.5 / 585 | 4.5 / 598.20 | 19.80 | 2.26 | 3 в продаже | 603.59 |
| BTC/USDT | 0.1 / 62 124 | нет | пусто | пусто | 0.1 в покупке | 62 248.50 |
| ETH/BTC | нет | 1.5 / 0.052395 | пусто | пусто | 1.5 в продаже | 0.05229 |

## 6. Связи с другими листами

- «Лэндинг» и «Закрытые» (только строки `L-…`) → «ИТОГО Лэндинг»: источники чисел.
- «Ввод» → Break even: формула читает комиссию с листа «Ввод».
- «ИТОГО Торговля» к Лэндингу не относится; «Закрытые» подключены с фильтром по ID `L-…`. «ИТОГО» складывает «ИТОГО Торговля» и «ИТОГО Лэндинг» (`specs/Промт ИТОГО.md`).

## 7. Проверки после любой правки

1. Пересчитать таблицу, ошибок (`#NAME?`, `#VALUE!`, `#REF!`, `#DIV/0!`) нет ни на одном листе.
2. Сверить итоги с независимым расчётом из сырых данных листов «Лэндинг» и «Закрытые» (строки `L-…`): количество и сумма по паре, P&L, P&L%, Break even.
3. Обратная проверка Break even: для остатка в покупке `Break even × (1 − f/100) × остаток + (H − E) = 0`, для остатка в продаже `(H − E) − Break even × (1 + f/100) × остаток = 0`.
4. Вписать новую пару в свободную строку 10–300: значения появляются, ошибок нет. Пара без сделок даёт пустые ячейки.
5. Формулы листа не ссылаются на «Торговля»; на «Закрытые» ссылаются с фильтром по ID `L-*`.
6. Документация (`specs/`, `architecture/`, `README.md`) совпадает с файлом, в репозитории одна рабочая версия таблицы.
7. После каждого изменения файла присылать актуальный xlsx в чат.

## 8. Чего не делать

- Макросы (VBA), рабочие кнопки, события.
- Подключать «Торговля» и брать из «Закрытых» строки без ID `L-*` (они принадлежат Торговле).
- Автоматический список пар формулами (ошибка в Excel 2021).
- Менять основной дизайн других листов, COLUMN_MAP и основной журнал.
- Вносить изменения без команды пользователя.
- Лишние цвета и декор вне палитры из `Дизайн Ввод.md`.

## 9. Открытые вопросы

- Фильтр по префиксу ID (`T-*`, `L-*`) требует, чтобы закрытые сделки сохраняли свой ID с правильной буквой; строка «Закрытых» с другим префиксом не попадёт ни в один свод.
- Break even, P&L и P&L% в закрытых сделках: правила пока не заданы.
- Фиксировать ли комиссию в строке на момент сделки, чтобы Break even не менялся при смене комиссии.
